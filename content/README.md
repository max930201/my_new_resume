# 個人履歷網站

李瑞勳｜嘉南藥理大學 資訊管理學系（進修部）

一個以「工程藍圖」風格打造的個人履歷網站，收錄真實部署、實際運作中的作品集，而非練習用的假資料。這份 README 整理面試官在瀏覽本網站與程式碼時，可能會關注的重點。

---

## 為什麼值得一看

- **不是模板堆疊出來的網站**：全部使用 HTML / CSS / JavaScript 手刻，沒有套用現成 UI 框架，版面架構、資料流、共用元件都是自己設計的。
- **作品集是真的上線在跑的系統**，不是課堂作業展示頁：18 個以上專案部署在 Netlify，其中多個串接 Firebase、Google Sheets、Notion 等後端服務，並且是為真實需求（治療師管理病人資料、洗衣店記帳、工廠薪資計算）而做的。
- **開發過程有留下紀錄**：`logs/` 資料夾內以日期歸檔每次開發異動，可以看到需求如何一步步擴充、規格如何被遵守與調整。

---

## 技術重點（給技術面試官）

### 1. 前端架構
- HTML / CSS / JavaScript **嚴格分離**，不混用 inline 樣式或行內 script。
- 共用元件（header、footer）只寫一次，透過 `fetch` 動態載入，首頁與子頁面共用同一份 `js/shared-render.js` 渲染邏輯，避免程式碼重複。
- 重複的視覺樣式（如藍圖風角標裝飾 `.corner-marks`）抽成共用 CSS 類別，而不是在照片框、作品卡、證書卡各自重寫一份。

### 2. 資料設計
- 所有內容以 **JSON 設定檔**管理（`profile.json`、`projects.json`、`skills.json`、`milestones.json`…），且**嚴格限制在兩層巢狀以內**——例如作品若有兩個連結，是用 `link` / `link2` 這種同層欄位處理，而不是塞進巢狀陣列。這代表在做資料結構設計時，有意識地在「彈性」與「單純」之間做取捨。
- 文字內容（自我介紹）以 Markdown 撰寫，搭配自製的輕量 Markdown 轉換器（`markdown-lite.js`），不依賴外部套件。

### 3. 後端／整合能力（作品集實證）
| 專案 | 展現的技術 |
|---|---|
| Ya3s 線上商城系統 | Firebase Authentication、Firestore 安全規則設計並實測驗證（會員僅能存取自己資料）、前後台分離部署、GAS 自動同步 Notion、防刷單節流機制 |
| 病人衛教卡系統 | Firebase 白名單登入、自動產生驗證碼機制、每日自動備份 |
| 工廠薪資 / 洗衣店記帳系統 | 串接 Google Sheets 作為資料庫，解決真實業主的記錄需求 |

### 4. 部署與版控
- 全站透過 **Netlify** 靜態部署，`netlify.toml` 設定簡潔（含基本安全性 Header）。
- 使用 Git / GitHub 進行版本控制。

### 5. 視覺設計判斷
- 刻意避開常見「AI 生成網站」的樣板感（例如浮誇漸層、無意義動畫），改採**工程藍圖美學**：IBM Plex Sans/Mono 字型、藍圖藍為主色、琥珀色僅保留給單一 CTA 按鈕，展現對視覺一致性與克制的設計判斷力。

## 學習歷程（給想了解人的面試官）

網站「關於我」與「學習歷程」區塊誠實記錄了一段非典型的求學路——因意外中斷原本升學計畫、比同屆晚兩年進入大學，最終選擇資管系並在近期開始接觸 AI 輔助開發（Vibe Coding）。這段經歷說明了這個作品集背後的學習動機與堅持。

---

## 建議面試官優先看的三個地方

1. **`config/projects.json` + 對應線上連結**：直接看真實系統長怎樣、解決了什麼問題。
2. **`logs/` 開發紀錄**：了解需求是如何被逐步釐清、規格如何被維持。
3. **首頁「技術能力」與「證照證書」區塊**：快速掌握技能全貌與檢定佐證。
